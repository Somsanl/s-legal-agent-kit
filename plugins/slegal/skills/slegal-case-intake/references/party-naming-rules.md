# กฎมาตรฐานการเปิดแฟ้มทุกประเภทงาน การตั้งชื่อคู่ความ สถานะพิเศษ และข้อมูลนิติบุคคล

เอกสารอ้างอิงฉบับนี้ใช้คู่กับสกิล `slegal-case-intake` เพื่อให้การเปิดแฟ้มใน `Cases` และการเก็บข้อมูลคู่ความใน `case_parties` รองรับทั้ง **คดีขึ้นศาล** และ **โปรเจกต์กฎหมายไม่ขึ้นศาล** ในที่เดียว รวมถึงนำไปออกเอกสารแบบพิมพ์ศาล `.docx` ได้ถูกต้อง 100%

---

## 0. โมเดลเปิดแฟ้มเดียวจบ (`Cases`) สำหรับงานไม่ขึ้นศาล vs คดีขึ้นศาล

สำนักงานใช้ตาราง `cases` เป็นศูนย์กลางของทุกเรื่อง:

| ประเภทงาน (`caseType`) | สถานะเริ่มต้น (`status`) | บทบาทคู่ความแนะนำ (`partyType`) | หมวดงานตั้งต้นแนะนำ (`initialFollowUpTask.taskCategory`) | การอ้างอิงกับผู้ใช้ |
|---|---|---|---|---|
| `ที่ปรึกษากฎหมาย` | `Pre-Litigation` | ลูกความ: `client` (`isOurClient: true`)<br/>คู่กรณี/หน่วยงาน (ถ้ามี): `counterparty` | `drafting` (ทำความเห็นกฎหมาย) หรือ `client_followup` | ชื่อเรื่อง + ชื่อลูกความ |
| `ร่าง/ตรวจสัญญา` | `Pre-Litigation` | ลูกความ: `client` (`roleDetail: "ผู้ว่าจ้าง/ผู้ซื้อ/..."`)<br/>คู่สัญญาอีกฝ่าย: `counterparty` | `drafting` (แท็บ `ร่างคำคู่ความ/เตรียมคดี`) | ชื่อเรื่อง + ชื่อลูกความ |
| `โนติส/เจรจาทวงถาม` | `Pre-Litigation` | เจ้าหนี้/ผู้แจ้งฝ่ายเรา: `client`<br/>ลูกหนี้/ผู้รับโนติส: `opponent` หรือ `counterparty` | `drafting` (ร่างโนติส) หรือ `opposing_followup` (ตามผลหลังส่ง) | ชื่อเรื่อง + ชื่อลูกความ |
| `จดทะเบียนธุรกิจ` | `Pre-Litigation` | ลูกความ/บริษัทที่จัดตั้ง: `client` | `document_prep` (แท็บ `ร่างคำคู่ความ/เตรียมคดี`) | ชื่อเรื่อง + ชื่อลูกความ |
| `แพ่ง`, `ผู้บริโภค`, `แรงงาน`, `อาญา`, `ปกครอง`, `ล้มละลาย` | `Court` (หรือ `Pre-Litigation` หากอยู่ชั้นเตรียมฟ้อง) | `plaintiff`, `defendant`, `petitioner`, `objector` ฯลฯ (หรือส่ง `client`/`opponent` เมื่อเป็นคดีฟ้องร้องทั่วไป) | `drafting` (ร่างฟ้อง/คำให้การ) หรือ `court_followup` | `เลขคดีดำ` (`blackCaseNo`) หรือ ชื่อเรื่อง + ลูกความเมื่อรอยื่นฟ้อง |

- เมื่อส่ง `partyType: "client"` ในงานไม่ขึ้นศาล ระบบจะแปลงเป็น `party_type = 'other'` พร้อม `is_our_client = true` และสรุปชื่อลงช่องลูกความของแฟ้มให้อัตโนมัติ
- เมื่อส่ง `partyType: "counterparty"` หรือ `"opponent"` ในงานไม่ขึ้นศาล ระบบจะแปลงเป็น `party_type = 'other'` พร้อม `is_our_client = false` และสรุปชื่อคู่สัญญา/คู่กรณีลงช่องคู่กรณีของแฟ้มให้อัตโนมัติ

## 1. กฎการเก็บชื่อตัวคู่ความแท้จริง (`name` + `titlePrefix`)

เก็บเฉพาะ **ชื่อตามกฎหมายของตัวคู่ความ** ลงใน `name` โดยไม่ปนคำว่า `"ที่ 1"` และไม่ปนข้อความ `"ในฐานะ..."` หรือ `"โดย..."`

### 1.1 บุคคลธรรมดา (`partyKind: "person"`)
- **ต้องมีคำนำหน้าชื่อตามกฎหมายติดหน้าชื่อเสมอ** และบันทึกคำนำหน้าแยกไว้ใน `titlePrefix` ด้วย:
  - คำนำหน้าสามัญ: `นาย`, `นาง`, `นางสาว`, `เด็กชาย`, `เด็กหญิง` (เขียนติดกับชื่อตัวโดยไม่เว้นวรรค เช่น `นายสมชาย ตัวอย่าง`, `นางสาววิภา ตัวอย่าง`)
  - **ห้ามใช้คำว่า `"คุณ"` เด็ดขาด** — ระบบ MCP จะปฏิเสธการบันทึก (`422`) ทันที ต้องถามผู้ใช้ว่าตามบัตรประชาชนเป็น `นาย`, `นาง`, หรือ `นางสาว`
  - **หลีกเลี่ยง `"น.ส."`** — ให้ใช้คำเต็ม `"นางสาว"` สำหรับหน้าคำคู่ความและแบบพิมพ์ศาลเสมอ
  - ยศตำรวจ / ทหาร / ราชทินนาม / สมณศักดิ์ / คำนำหน้าวิชาชีพที่ใช้ตามบัตรราชการ: เช่น `พ.ต.ต. สมชาย ตัวอย่าง`, `ว่าที่ ร.ต. อนันต์ ตัวอย่าง` (ระบุยศใน `titlePrefix` ให้ตรงตามบัตรราชการ)
  - ชาวต่างชาติ: ใช้ `Mr.`, `Mrs.`, `Ms.`, `Miss` ตามหนังสือเดินทาง หรือทับศัพท์ไทยตามเอกสารราชการ

### 1.2 นิติบุคคล (`partyKind: "company"` หรือ `"organization"`)
- **ห้ามใช้คำย่อ `บจก.`, `บมจ.`, `หจก.`, `หสม.` เด็ดขาด** — ระบบ MCP จะปฏิเสธการบันทึก (`422`) ทันที
- รูปแบบมาตรฐานตามชนิดนิติบุคคล (`entitySubtype`):
  - บริษัทจำกัด (`entitySubtype: "บริษัทจำกัด"`): `บริษัท [ชื่อ] จำกัด`
  - บริษัทมหาชนจำกัด (`entitySubtype: "บริษัทมหาชนจำกัด"`): `บริษัท [ชื่อ] จำกัด (มหาชน)`
  - ห้างหุ้นส่วนจำกัด (`entitySubtype: "ห้างหุ้นส่วนจำกัด"`): `ห้างหุ้นส่วนจำกัด [ชื่อ]`
  - ห้างหุ้นส่วนสามัญนิติบุคคล (`entitySubtype: "ห้างหุ้นส่วนสามัญนิติบุคคล"`): `ห้างหุ้นส่วนสามัญนิติบุคคล [ชื่อ]`
  - นิติบุคคลอาคารชุด (`entitySubtype: "นิติบุคคลอาคารชุด"`): `นิติบุคคลอาคารชุด [ชื่อ]`
  - นิติบุคคลหมู่บ้านจัดสรร (`entitySubtype: "นิติบุคคลหมู่บ้านจัดสรร"`): `นิติบุคคลหมู่บ้านจัดสรร [ชื่อ]`
  - มูลนิธิ / สมาคม / สหกรณ์ / วัด / หน่วยงานรัฐ (`partyKind: "organization"`): สะกดชื่อเต็มตามตราสารจัดตั้งหรือกฎหมายจัดตั้งหน่วยงาน

## 2. กฎการแยกสถานะพิเศษตามกฎหมาย (`specialCapacityType` + `specialCapacityLabel`)

ห้ามเขียนข้อความสถานะพิเศษปนลงใน `name` ให้แยกใส่ใน `specialCapacityType` และ `specialCapacityLabel` เพื่อให้ระบบประกอบชื่อเต็ม (`composedName`) และชื่อย่อได้ถูกบริบท:

| กรณีตามกฎหมาย | `name` (ตัวคู่ความแท้จริง) | `specialCapacityType` | ตัวอย่าง `specialCapacityLabel` | ผลลัพธ์เมื่อประกอบลงหน้าคำคู่ความ |
|---|---|---|---|---|
| **ผู้จัดการมรดก** (ฟ้องหรือถูกฟ้องในฐานะผู้จัดการมรดก) | `นางสมศรี ตัวอย่าง` | `estate_administrator` | `ในฐานะผู้จัดการมรดกของนายสมชาย ตัวอย่าง ผู้ตาย` | `นางสมศรี ตัวอย่าง ในฐานะผู้จัดการมรดกของนายสมชาย ตัวอย่าง ผู้ตาย` |
| **ผู้เยาว์** (ผู้เยาว์เป็นตัวความ โดยมีผู้แทนโดยชอบธรรมดำเนินคดีแทน) | `เด็กชายก้อง ตัวอย่าง` | `legal_guardian` | `โดย นางสมศรี ตัวอย่าง ผู้แทนโดยชอบธรรม` | `เด็กชายก้อง ตัวอย่าง โดย นางสมศรี ตัวอย่าง ผู้แทนโดยชอบธรรม` |
| **คนไร้ความสามารถ / เสมือนไร้ความสามารถ** | `นายวิชัย ตัวอย่าง` | `curator_guardian` | `โดย นางสมศรี ตัวอย่าง ผู้อนุบาล` (หรือ `ผู้พิทักษ์`) | `นายวิชัย ตัวอย่าง โดย นางสมศรี ตัวอย่าง ผู้อนุบาล` |
| **บุคคลธรรมดามอบอำนาจให้ฟ้อง/ดำเนินคดีแทน** | `นายสมชาย ตัวอย่าง` | `poa_holder` | `โดย นายธนากร ตัวอย่าง ผู้รับมอบอำนาจ` | `นายสมชาย ตัวอย่าง โดย นายธนากร ตัวอย่าง ผู้รับมอบอำนาจ` |
| **เจ้าพนักงานพิทักษ์ทรัพย์** (คดีล้มละลาย) | `เจ้าพนักงานพิทักษ์ทรัพย์ของนายเอก ตัวอย่าง` | `bankruptcy_receiver` | `ในฐานะเจ้าพนักงานพิทักษ์ทรัพย์ของ...` | ประกอบตามรูปแบบศาลล้มละลาย |
| **นิติบุคคลเลิกบริษัทอยู่ระหว่างชำระบัญชี** | `บริษัท ตัวอย่าง จำกัด` | `liquidator` | `โดย นายสมชาย ตัวอย่าง ผู้ชำระบัญชี` | `บริษัท ตัวอย่าง จำกัด โดย นายสมชาย ตัวอย่าง ผู้ชำระบัญชี` |

> **หมายเหตุสำหรับผู้รับมอบอำนาจ / ผู้แทน**: นอกจากการใส่ `specialCapacityLabel` แล้ว ให้เพิ่มชื่อ เลขบัตรประชาชน และรายละเอียดหนังสือมอบอำนาจของผู้รับมอบอำนาจลงใน `relatedPersons[]` (`relationType: "attorney_in_fact"`, `authorityNote: "ตามหนังสือมอบอำนาจลงวันที่ ..."`) เสมอ เพื่อให้สกิล `thai-legal-drafting` ดึงไปเขียนบรรยายสถานะโจทก์ใน `ข้อ ๑` ได้ครบถ้วน

## 3. กฎลำดับคู่ความ (`sideOrdinal`) และการคำนวณคำลงท้าย `ทนาย...`

1. **ลำดับในฝั่งเดียวกัน (`sideOrdinal`)**:
   - คู่ความคนเดียวในฝั่งนั้น: `sideOrdinal: 1` -> ระบบแสดง `นาย ก.` (ไม่เติมคำว่า `ที่ 1`)
   - คู่ความตั้งแต่ 2 คนขึ้นไปในฝั่งเดียวกัน: `sideOrdinal: 1`, `2`, `3`... -> ระบบสร้างตัวแปรได้ 4 โหมดอัตโนมัติ:
     - `full_list` (คั่นลูกน้ำบรรทัดเดียว): `นาย ก. ที่ 1, นาย ข. ที่ 2, นาย ค. ที่ 3`
     - `multiline` (แยกบรรทัดรายคน)
     - `et_al_short` (ย่อหน้าปกสั้น): `นาย ก. กับพวก`
     - `et_al` (ย่อหน้าปกพร้อมจำนวน): `นาย ก. กับพวกรวม 3 คน`
2. **การคำนวณฐานะลูกความฝ่ายเราและคำลงท้ายทนาย (`isOurClient` -> `my_party_role` / `drafter_role`)**:
   - เป็นทนายให้จำเลยคนเดียวในคดีที่มีจำเลยคนเดียว -> `ทนายจำเลย`
   - เป็นทนายให้จำเลยที่ 2 คนเดียว (ในคดีที่มีจำเลย 3 คน) -> `ทนายจำเลยที่ 2`
   - เป็นทนายให้จำเลยที่ 1 และที่ 2 -> `ทนายจำเลยที่ 1 และที่ 2`
   - เป็นทนายให้จำเลยที่ 1, 2 และ 3 (เรียงติดกัน) -> `ทนายจำเลยที่ 1 ถึงที่ 3`
   - เป็นทนายให้จำเลยที่ 1, 3 และ 4 (เว้นลำดับ) -> `ทนายจำเลยที่ 1, ที่ 3 และที่ 4`
   - คดีไม่มีข้อพิพาท (`partyType: "petitioner"`, `isOurClient: true`) -> `ทนายผู้ร้อง`

## 4. ข้อมูลหนังสือรับรองนิติบุคคล (DBD Checklist)

เมื่อคู่ความ (โดยเฉพาะโจทก์หรือลูกความฝ่ายเรา) เป็นนิติบุคคล ให้สกัดข้อมูลจากหนังสือรับรองบริษัทให้ครบทุกช่องต่อไปนี้:
1. `name`: ชื่อนิติบุคคลเต็มตามหน้าแรกหนังสือรับรอง
2. `entitySubtype`: เช่น `บริษัทจำกัด`, `บริษัทมหาชนจำกัด`, `ห้างหุ้นส่วนจำกัด`
3. `registrationNo` & `taxId`: เลขทะเบียนนิติบุคคล 13 หลัก
4. `registrationOffice`: เช่น `สำนักงานทะเบียนหุ้นส่วนบริษัทกรุงเทพมหานคร`
5. `certificateIssuedDate`: วันที่ออกหนังสือรับรอง (`YYYY-MM-DD`) — เตือนเมื่อเกิน **30 วัน** และเตือนให้คัดใหม่เมื่อเกิน **90 วัน**
6. `authorityCondition`: ข้อความเงื่อนไขการลงชื่อผูกพันนิติบุคคลและประทับตราสำคัญทุกตัวอักษร
7. `corporateObjectivesSummary`: สรุปวัตถุประสงค์ข้อที่เกี่ยวกับมูลคดี เพื่อใช้ร่างคำฟ้อง `ข้อ ๑`
8. `address`: ที่ตั้งสำนักงานใหญ่แยกทุกช่อง (`houseNo`, `building`, `floorNo`, `moo`, `soi`, `road`, `subdistrict`, `district`, `province`, `postalCode`)
9. `relatedPersons[]`: กรรมการผู้มีอำนาจลงนาม (`relationType: "authorized_representative"`, `isSignatory: true`, `isPrimary: true`) และผู้รับมอบอำนาจช่วง (`relationType: "attorney_in_fact"`)
